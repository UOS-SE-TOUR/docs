## 파일 이름과 버전

- 파일명은 `문서명_최백문_v버전`으로 붙인다: `프로젝트계획서_최백문_v0.1.hwp`
- `0.x` 작업 중, `1.0` 제출본, 제출 뒤 수정은 `1.1 …`, 다음 제출은 `2.0`
- 양식에 "문서버전"·변경 기록 표가 있는 산출물은 그 번호를 파일명 버전과 맞춘다 (계획서 양식에는 없다)
- 문서 하나는 한 번에 한 사람만 고친다 (hwp·doc는 병합이 안 된다)
- 제출본(`1.0`, `2.0` …)은 PDF도 같이 올린다. GitHub에서 hwp 미리보기가 안 된다
- 그림은 원본과 함께 올린다. png 옆에 StarUML `.mdj`, html 같은 원본을 두어야 나중에 고칠 수 있다

## 작업 흐름

1. 산출물은 문서마다 이슈를 하나 만들고 마일스톤을 건다. 그 밖의 작업(README 등)은 필요할 때만 이슈를 만든다.
2. 브랜치를 따서 작업하고 PR로 올린다. main에 바로 올리지 않는다.
3. 버전 하나에 PR 하나. hwp는 GitHub에서 비교가 안 되니 PR 본문에 바뀐 점을 적는다.
4. 다른 사람이 쓴 파일을 대신 올릴 때는 커밋 작성자를 실제 작성자로 지정한다.

   ```sh
   gh api users/아이디 --jq .id   # 숫자 ID 확인
   git commit --author="이름 <숫자ID+아이디@users.noreply.github.com>" -m "..."
   ```

5. 머지한 브랜치는 지운다.
